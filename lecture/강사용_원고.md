## 1. 수업 조언자란?

> **[강사 메모 — S05 / 6–9분]**
> S05의 옆자리 대화는 1분으로 짧게 자릅니다.
> "매번 내 교과를 설명해야 한다", "대화가 사라진다" 같은 답이 자연스럽게 나옵니다.
> 이 답을 S06 비교표로 바로 연결하면 흐름이 좋습니다.

### 일반 AI 채팅과 무엇이 다른가

| | 일반 AI 채팅 | 수업 조언자 프로젝트 |
|---|---|---|
| 내 교과 정보 | 매번 새로 설명해야 함 | 한 번 설정하면 유지됨 |
| 내 학급·학교 상황 | 반영 안 됨 | 처음부터 알고 있음 |
| AI의 행동 방식 | 무엇이든 대답하려 함 | 설계된 원칙대로 작동 |
| 대화 맥락 | 창을 닫으면 사라짐 | 프로젝트 안에 축적됨 |

### ChatGPT 프로젝트 기능이란?

> **[강사 메모 — S07 / 9–12분]**
> S07에서 ChatGPT 화면을 실제로 보여줍니다. 왼쪽 메뉴의 "프로젝트"를 클릭해서
> 프로젝트 목록 화면, 프로젝트 내부의 지침·파일·채팅 구조를 30초만 보여줍니다.
> 기능 설명보다 "이렇게 생겼습니다"를 보여주는 것이 먼저입니다.

### Layer 구조: 두 가지를 설정한다

**Layer 1 — 조언자의 행동 원칙** (이미 완성됨, 오늘 붙여넣기만 하면 됨)

이 조언자가 어떻게 행동할지를 정하는 규칙 문서입니다.
"교사의 판단을 대체하지 않고 질문자·보완자·점검자로 행동한다",
"기준 문서를 수호한다", "페이싱을 지킨다" 같은 원칙들이 담겨 있습니다.

**Layer 2 — 내 맥락 계약** (오늘 함께 만드는 것)

조언자가 나를 알기 위한 정보입니다.
- 내 교과와 학교급
- 내 수업 철학과 지향
- 내 학급 상황
- 내가 조언자에게 기대하는 역할

> **[강사 메모 — S08–S09 / 12–21분]**
> S08에서 Layer 1 파일을 잠깐 펼쳐서 보여주면 좋습니다.
> 전체를 읽을 필요 없고, "이런 내용이 들어있다"는 것을 보여주는 것만으로 충분합니다.
> S09는 "오늘 같이 만드는 것"임을 강조합니다.
> 항목을 설명할 때 "조언자가 먼저 질문을 해요, 그냥 답하시면 됩니다"라고 미리 안심시킵니다.

### ChatGPT 프로젝트 설정하기

> **[강사 메모 — S14–S16 / 35–48분]**
> 각 단계를 강사가 먼저 화면으로 시연하고, 참여자가 따라합니다.
> "저를 따라서 함께 해보시겠습니다"라고 시작합니다.
> 1단계(프로젝트 생성): ChatGPT 화면의 왼쪽 메뉴에 "프로젝트"가 없는 경우,
>   계정 설정에서 확인하거나 스크롤을 내려보도록 안내합니다.
> 2단계(프로젝트 지침 붙여넣기): 파일이 열리지 않는 분은 텍스트 편집기로 열도록 안내합니다.
>   이 과정은 생략하지 않습니다. 지침 칸에 Layer 1이 들어가야 조언자가 이후 모든 대화에서 같은 원칙으로 작동합니다.
> 3단계(파일 업로드): 파일이 어디 있는지 다시 한번 확인해줍니다.
> 저장 확인: 참여자 화면에서 프로젝트 지침이 저장되었는지, Layer 2 파일이 업로드되었는지 눈으로 확인합니다.
> 문제가 있는 분은 옆 사람의 도움을 받거나 강사가 순회합니다.

**1단계. 프로젝트 만들기**
- chatgpt.com 접속 → 왼쪽 메뉴 **"프로젝트"** → **"새 프로젝트"**
- 프로젝트 이름 입력 (예: "수업 설계 조언자", "○○교과 수업 조언자")

**2단계. Layer 1 프로젝트 지침 붙여넣기**
- 프로젝트 설정 → **"지침"** 칸 클릭
- `ChatGPT용_수업설계조언자_프로젝트지침` 파일의 전체 내용을 복사해 붙여넣기
- 저장

**3단계. Layer 2 파일 업로드**
- 프로젝트 설정 → **"파일"** 또는 **"소스 추가"** 클릭
- `Layer_2_수업설계조언자` 파일 업로드
- 저장

**4단계. 첫 대화 시작**
- 프로젝트 안에서 새 채팅 시작
- 조언자가 Layer 2 파일을 읽고 구성 대화를 시작합니다

### Layer 2 구성 대화 안내

> **[강사 메모 — S17–S18 / 48–80분]**
> Layer 2 대화 시작 전에 "조언자가 먼저 질문을 합니다. 여러분은 답만 하시면 됩니다"라고 안내합니다.
> 강사가 먼저 자신의 계정으로 짧게 시연합니다. 첫 메시지를 보내고, 조언자가 어떻게 반응하는지 1~2분만 보여줍니다.
> 이후 참여자 자유 진행 시간(25분)에 강사는 순회합니다.
>
> 순회 시 확인:
> - 조언자 응답이 이상하게 나오는 분 → 지침이 올바르게 붙여넣어졌는지 확인
> - 대화가 막힌 분 → "조언자가 뭐라고 물어보나요?" 확인 후 답변 방향 안내
> - 한도 초과된 분 → S12 슬라이드로 돌아가 Gemini 전환 안내
>
> ⏩ 시간 부족 시 (80분이 되기 전에 아직 진행 중인 분 많을 때):
> "지금 진행하시는 것은 집에서도 이어가실 수 있습니다. 5분 후 다음으로 넘어가겠습니다."

첫 메시지를 보내면 조언자가 Layer 2를 채우기 위한 질문을 시작합니다.
준비 카드를 보면서 답변하세요.

조언자가 묻는 항목:
- **역할 설정**: 내 수업 철학, 조언자에게 기대하는 역할, 피하고 싶은 방식
- **교사 프로필**: 교과, 학교급·학년, 교직 경력
- **학급 맥락**: 학생 수준·특성, 특별히 고려할 사항
- **운영 여건**: 시수, 교실 환경, 활용 가능한 도구
- **기준 문서**: 내 수업에서 기준이 되는 문서 (교육과정, 성취기준, 내가 쓴 단원 설계 등)

> **팁**: 모든 항목을 한 번에 완성하려 하지 않아도 됩니다.
> 오늘은 시작만 해도 충분합니다. 이후 대화를 거치며 자연스럽게 채워집니다.

## 5. AI로 수업 도구 만들기

> **[강사 메모 — S22–S24 / 105–112분]**
> S22–S24는 전환점입니다. "지금까지는 대화형 조언자를 만들었고, 이번엔 다른 종류의 도구입니다"라고 구분해서 말합니다.
> S23에서 터미널 시연은 선택 사항입니다. 분위기를 보고 결정합니다.
>   시연한다면: 터미널을 열고 `claude` 명령어를 실행해서 "안녕"이라고 입력하는 정도면 충분합니다.
>   하지 않는다면: "터미널에서 이렇게 실행합니다"라고 말만 해도 됩니다.
> S24는 반드시 넣습니다. "오늘 설치 안 해도 됩니다"를 명확히 해야 불안이 사라집니다.
>
> ⏩ 시간 부족 시: S22–S24를 3분으로 압축. "웹에서 쓰는 것과 설치해서 쓰는 것이 있는데, 오늘은 웹으로 합니다" 한 마디로 정리.

### 두 가지 AI 사용 방식

AI를 사용하는 방법은 크게 두 가지입니다.

**웹 기반 AI** — 지금까지 해온 방식

브라우저에서 대화합니다. 결과물이 화면에 텍스트로 출력됨 → 복사해서 사용

**로컬 설치 AI** — 컴퓨터에 설치해서 사용

AI를 내 컴퓨터에 설치해 터미널에서 사용합니다.
말로 요청하면 AI가 내 컴퓨터 파일을 **직접 읽고 생성하고 수정**합니다.

| | 웹 기반 AI | 로컬 설치 AI |
|---|---|---|
| 대표 도구 | ChatGPT, Gemini, Claude | Claude Code (Anthropic), Codex (OpenAI) |
| 파일 직접 생성 | ✗ (복사해서 저장) | ✓ (자동으로 생성됨) |
| 설치 필요 | ✗ | ✓ (터미널 사용) |
| 기술 난이도 | 낮음 | 중간 |
| 적합한 용도 | 텍스트 작성, 조언, 대화 | 파일·웹앱 제작 |

**오늘 실습**: 웹 기반 AI(ChatGPT)에서 직접 웹앱을 요청해봅니다.

### 수업 도구 웹앱이 수업의 킥이 되는 이유

> **[강사 메모 — S25–S30 / 112–128분]**
> S25의 두 조건을 먼저 보여주고, S26의 질문으로 사례 소개로 넘어갑니다.
> S26에서 잠깐 참여자 반응을 받습니다. 10초면 충분합니다.
> S27을 보여줄 때 "왜 그럴까요?"를 한 번 더 물어봐도 좋습니다.
> S28 시연 순서:
>   1. 앱 화면 열기, 배너 질문 읽기
>   2. 기본값(n=20, p=0.7, r=0) 상태에서 준비 부족 확률 41.6% 보여주기
>   3. "자동 실행" → 빨간 막대 나오는 것 확인
>   4. r 슬라이더 올리기 → 확률 변화 확인
>   5. n을 100으로 → 같은 비율인데 더 안정적
>   총 시연 시간: 5분
> S29는 "앱이 전부가 아니다"를 강조합니다. 학습지도 보여주면 좋습니다.
> S30에서 반응을 받는 것이 중요합니다. 교사들의 아이디어가 나오면 그것이 다음 웹앱의 씨앗입니다.
> 단, 이 블록은 프로젝트 지침 만들기 이후의 확장 사례입니다. 조언자 프로젝트 완성이 본 연수의 필수 목표라는 점을 흐리지 않습니다.

AI로 도구를 만드는 것 자체가 목적이 아닙니다.
**학생들이 직관으로 이해하기 어려운 지점을 시각화하는 것**이 목적입니다.

> 학생들이 잘못된 직관을 갖고 있고,
> 말로 설명하거나 숫자를 보여주는 것만으로는 그 직관이 잘 바뀌지 않을 때

**수학 수업 사례**

확률과 통계 수업에서 학생들은 이런 직관을 갖고 옵니다.

> "참석 확률이 70%니까 70%만 준비하면 충분하지 않나요?"

이 직관은 틀렸습니다. 기댓값만큼 준비하면 약 10번 중 4번은 준비가 부족합니다.

이 웹앱의 구조:
- 슬라이더: 신청자 수 / 참석 확률 / 여유 준비 비율 조절
- 결과: 준비 부족 확률이 실시간으로 변함
- 시뮬레이션: "자동 실행"으로 수백 번 반복 → 이론값과 실험값이 수렴

**내 교과에서 찾아보기**

> 여러분 교과에서 학생들이 틀린 직관을 갖고 오는 지점이 있나요?
> 그 직관을 깨는 데 움직이는 시뮬레이션이 효과적인 경우는?

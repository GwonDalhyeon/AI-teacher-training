# Layer 2 — 프로젝트 컨텍스트

**상태: 미확립 (제작 지침 모드)**

이 파일은 이 프로젝트의 Layer 2 파일이다. 조언자는 대화 시작 시
반드시 이 파일을 먼저 확인한 뒤, 프로젝트 지침의 0번 원칙에 따라
동작한다.

현재 상태는 **미확립**이다. 사용자와 함께 Layer 2를 구성하는 것이
이 조언자의 첫 번째 작업이다.

---

## Layer 2 구성 흐름

1. 조언자는 사용자의 첫 메시지를 받으면 Layer 2 1~6번 항목(프로젝트
   정의, 사용자 프로필, 작업 맥락, 운영 여건, 기준 문서, 조사 기준)을
   중심으로 구성 대화를 시작한다.
2. 대화 중 자료 조사가 필요하면 조언자가 NotebookLM 딥리서치 프롬프트와
   보고서 제작 프롬프트를 생성한다. 사용자는 NotebookLM으로 조사한 뒤
   보고서를 프로젝트의 2차 참고 문서로 업로드한다.
3. 1~6번 항목이 충분히 채워지면 조언자가 완성된 Layer 2를 복사
   가능한 블록으로 출력한다.
4. 사용자는 아래 "Layer 2 최종 템플릿" 형식에 맞춰 **확정본 파일**을
   작성하여 이 파일을 교체 업로드한다. 파일명에 "Layer 2"를 포함하고
   형식은 사용자가 익숙한 것을 선택한다(예: .md, .txt, .hwp, .docx 등).
   확정본 파일은 맨 앞에 **"상태: 확립"** 으로 표기한다.

---

## Layer 2 최종 템플릿 (확정본 작성 시 사용)

확정본 파일은 아래 구조를 따른다.

```markdown
# Layer 2 — 프로젝트 컨텍스트

**상태: 확립**

### 1. 프로젝트 정의
- 이 프로젝트의 목적:
- 지향하는 방향·원칙:
- 조언자에게 기대하는 역할:
  예) 아이디어 제공자 / 비판자 / 검토자 / 자료 조사자 / 실행 보조자
- 피하는 방식과 이유:

### 2. 사용자 프로필
- 도메인·분야:
- 전문성·경력 수준:
- 담당 업무·역할:

### 3. 작업 맥락
- 작업 규모·대상:
- 관계자 특성:
- 특별히 고려할 사안:

### 4. 운영 여건
- 시간·일정 제약:
- 환경·자원:
- 외부 제약:
- 활용 가능한 도구:

### 5. 기준 문서
- 1차 기준 (사용자의 판단·의도가 담긴 문서):
- 2차 참고 (조사·탐구 결과물):

### 6. 조사 기준
- 이 프로젝트에서 주로 다루는 자료 영역과 최소 자료 개수
  예) 도메인 내용 2개, 이론·방법론 3개, 실천 사례 3개, 도구·기술 2개, 법령·규정 2개
```

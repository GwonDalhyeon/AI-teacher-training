# 스마트 도시 균형 실험실 작업지시서

## 1. 기본 정보

- 교과: 도시의 미래탐구
- 관련 단원: 주제 7. 첨단 산업과 모빌리티의 발달, 스마트 도시
- 대상 파일: `webapps/smart-city-balance/index.html`
- 앱 성격: 도시 기술 선택과 공공성 균형을 보여 주는 시연형 웹앱
- 구현 우선순위: 높음. 도시·법 후보 중 연수 시연용으로 가장 직관적이다.

## 2. 핵심 의도

깨야 할 직관:

> 스마트 도시는 첨단 기술을 많이 넣을수록 좋은 도시다.

아하 모먼트:

> 스마트 도시는 편리성만의 문제가 아니라 데이터 수집, 시민 참여, 비용, 형평성, 신뢰의 균형 문제다.

교과서 기반:

- 스마트 도시는 인공지능, 빅 데이터, 사물 인터넷 등 첨단 기술을 활용하여 도시를 계획·관리하고 삶의 질을 개선하려는 도시이다.
- 스마트 도시의 성공과 실패는 의미 있는 데이터를 확보하고 잘 활용하는 데 달려 있다.
- 그러나 데이터 수집과 기술 중심 개발은 개인정보, 감시, 통제, 공간 불평등 문제를 만들 수 있다.
- 리빙랩 모델처럼 시민이 문제 발견과 정책 설계에 참여하는 상향식 접근도 중요하다.

## 3. 화면 구조

1. 상단: 앱 제목, 깨야 할 직관, 핵심 질문
2. 중앙 왼쪽: 가상의 도시 보드
3. 중앙 오른쪽: 스마트 기술 카드 목록
4. 하단 또는 사이드: 도시 상태 지표 5개
5. 결과 카드: 현재 도시에 대한 한 문장 진단

## 4. 주요 조작

기술 카드는 6개 정도로 제한한다.

- 스마트 도로
- 스마트 주차
- 폐기물 관리
- 스마트 가로등
- 대기 오염 관리
- 스마트 그리드

조작 방식:

- 기술 카드를 클릭하면 도시 보드에 적용된다.
- 적용된 기술은 다시 클릭하면 제거된다.
- `기술 효율 우선`, `시민 참여 우선`, `균형형` 프리셋 버튼을 제공한다.
- `데이터 수집 수준`은 3단계 토글로 둔다: 낮음, 보통, 높음.

## 5. 결과 지표

각 기술과 데이터 수집 수준에 따라 아래 지표가 즉시 변해야 한다.

- 편리성
- 비용 부담
- 개인정보 위험
- 형평성
- 시민 신뢰

표현 방식:

- 막대 그래프 5개 또는 반원 게이지 5개
- 색상은 긍정 지표와 위험 지표를 구분한다.
- 수치는 보조 정보로만 사용하고, 변화가 눈에 들어오게 한다.

지표 계산은 실제 데이터를 흉내 내지 말고, 수업용 규칙 기반 점수로 만든다.

- 기술 카드마다 편리성, 비용 부담, 개인정보 위험, 형평성, 시민 신뢰에 미치는 값을 미리 정한다.
- `데이터 수집 수준`은 편리성과 개인정보 위험에만 강하게 영향을 준다.
- `시민 참여 우선` 프리셋은 기술 수를 줄이는 대신 형평성과 신뢰를 높인다.
- 화면에 점수 산식은 보이지 않게 하고, 필요하면 코드 주석에만 간단히 남긴다.

## 6. 필수 상호작용

- 기술을 많이 넣으면 편리성은 올라가지만 비용과 개인정보 위험도 함께 올라간다.
- 데이터 수집 수준을 높이면 교통·관리 효율은 올라가지만 개인정보 위험과 시민 신뢰 저하가 나타난다.
- 시민 참여 프리셋은 편리성 상승 폭은 작아도 형평성과 신뢰가 높게 나타난다.
- 균형형 프리셋은 모든 지표가 극단으로 치우치지 않게 보여 준다.

## 7. 시연 흐름

1. 강사가 질문한다: "스마트 기술을 많이 넣으면 무조건 좋은 도시가 될까요?"
2. `기술 효율 우선` 프리셋을 누른다.
3. 편리성은 높지만 개인정보 위험과 비용 부담이 커지는 것을 보여 준다.
4. `시민 참여 우선` 프리셋을 누른다.
5. 신뢰와 형평성이 달라지는 것을 비교한다.
6. 기술 카드를 1-2개 직접 바꾸며 균형점을 찾아 본다.

## 8. 완료 기준

- 첫 화면만 보고도 기술 선택과 지표 변화의 관계를 알 수 있어야 한다.
- 30초 안에 강사가 시연 흐름을 이해할 수 있어야 한다.
- 지표가 너무 많아 복잡해 보이지 않아야 한다.
- 기술 카드 선택 후 결과 변화가 즉시 보여야 한다.
- 모바일에서는 기술 카드가 아래로 내려가도 지표와 결과가 겹치지 않아야 한다.

## 9. 피해야 할 것

- 실제 도시 데이터 API 연동
- 실제 기업이나 특정 도시 평가처럼 보이는 표현
- 너무 많은 도시 기술 목록
- 개인정보 문제를 단순 경고 문구로만 표시
- 사용자가 긴 텍스트를 입력해야 하는 구조
- 퀴즈나 OX 문제 형식

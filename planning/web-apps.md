# Web App Guidelines

## 철학

웹앱 시연의 목적은 두 가지다.

1. **수업 설계 관점 전달**: "어떤 순간에 웹앱이 수업의 킥이 되는가"를 직접 경험하게 한다
2. **가능성 인식**: "AI로 이런 것도 만들 수 있다"는 감각을 심는다

참여자가 보고 나서 얻어야 할 것은 "내 교과에도 학생들이 직관으로 틀리는 지점이 있는데, 거기에 쓸 수 있겠다"는 감각이다.

## 기술 스택

- GitHub Pages에서 구동 가능한 정적 파일만 사용
- 단일 `index.html` — Tailwind CSS CDN, vanilla JS
- 외부 API 호출 없음, 백엔드 없음

## 웹앱 제작 기준

좋은 웹앱의 조건:

1. **직관과 현실의 충돌**: 학생(또는 교사)이 가진 잘못된 직관이 있고, 그것을 시뮬레이션으로 깰 수 있다
2. **변수 조작 → 즉각적인 시각 변화**: 슬라이더·버튼으로 값을 바꾸면 결과가 바로 바뀐다
3. **아하 모먼트**: 정지된 설명이나 숫자로는 전달하기 어려운 개념이 움직임으로 이해된다
4. **교과 내용 밀착**: 교과서 내용을 그대로 다룬다. 교과 이름만 바꾸는 범용 도구가 아님

피해야 할 것:

- 퀴즈·OX 문제·분류 게임 형태 — 단순 상호작용, 교과 내용 이해와 직결 안 됨
- 정보 나열·비교표 수준 — 애니메이션·인터랙션 없이 텍스트만
- 입력받아 텍스트 출력하는 형태 — AI 챗봇 흉내

시연용 앱의 조작 원칙:

- 폴더와 파일명은 영문으로 작성하고, 웹에서 보이는 제목·설명·버튼만 한글로 표시한다
- 내용을 잘 모르는 학생이나 타교과 교사도 10초 안에 "무엇을 바꾸면 무엇이 달라지는지" 볼 수 있어야 한다
- 자유도를 높이기보다 강사가 보여줄 변화 2-4개를 버튼이나 프리셋으로 제한한다
- 원인과 결과를 같은 화면에 둔다: 조작 영역, 움직임, 결과 표시가 서로 멀리 떨어지지 않게 한다
- 수치 표시는 보조로만 사용하고, 핵심 이해는 움직임·색·강도·방향 변화로 전달한다

## Block 4 시연 설계

### 도입: 강사 수학 수업 사례 (10분)

**시연 앱**: `math-webapps/probability-statistics/sample-proportion-event-readiness/`

**수업 설계 의도 (강사 멘트 핵심)**

이 앱을 만든 출발점은 학생들이 가진 하나의 직관이다:

> "참석 확률이 70%니까 70%만 준비하면 충분하다."

이 직관은 틀렸다. 70%만 준비하면 10번 중 4번은 준비가 부족하다.
교과서로도 설명할 수 있지만, 직접 시뮬레이션을 돌려보면서 빨간 막대가 계속 나오는 걸 보는 경험이 다르다.

**앱 구조 설명 포인트**
- 상단 배너의 질문이 곧 수업의 출발점: *"이 판단, 얼마나 자주 틀릴까요?"*
- 슬라이더 3개(n, p, r)로 상황을 바꾸면 준비 부족 확률이 실시간으로 변한다
- "자동 실행" 버튼으로 수백 번 시뮬레이션 → 이론값과 실험값이 수렴하는 것을 본다
- 학습지가 앱과 함께 묶여 수업 시퀀스를 이룬다 (앱 없이 학습지만 쓰면 반쪽)

**강사가 전달할 수업 설계 흐름**

    학생 직관 확인 → 앱으로 직관 충돌 경험 → 학습지로 수치 확인 →
    여유 준비 비율 조절 실험 → 의사결정 토론

**연수 참여자에게 던질 질문**

> "여러분 교과에서 학생들이 틀린 직관을 갖고 오는 지점이 있나요?  
> 그 직관을 깨는 데 정지된 그림보다 움직이는 시뮬레이션이 더 효과적인 경우가 있나요?"

이 질문이 교사들이 자기 교과의 웹앱 아이디어를 떠올리는 계기가 된다.

### 이어지는 시연: 교과별 웹앱 갤러리 (20분)

수학 사례에서 끌어낸 설계 원칙을 다른 교과 앱으로 확인한다. 이제 시연 앱이 여러 개이므로 모든 앱을 깊게 조작하지 않는다. 목록 페이지를 먼저 열어 "교과가 달라도 같은 설계 구조가 반복된다"는 점을 보여준 뒤, 대표 3개만 압축 시연한다.

시연용 목록 페이지:

`https://gwondalhyeon.github.io/AI-teacher-training/webapps/`

**강사가 강조할 공통 구조**

    깨야 할 직관 → 조작할 변수 → 눈에 보이는 변화 → 수업 질문

**대표 시연 순서 (권장)**

1. **수평 투사 운동** (통합과학1)
   - 직관: "빠르게 던지면 더 빨리 떨어질 것 같다"
   - 앱: `동시에 발사` 버튼 + 제한된 속도 프리셋 → 수평 이동 거리는 달라지지만 낙하 시간은 동일
   - 킥: 수평·수직 운동의 독립성
   - URL: `https://gwondalhyeon.github.io/AI-teacher-training/webapps/horizontal-projectile/`

2. **폭염 취약 지역 커뮤니티 매핑** (도시의 미래탐구)
   - 직관: "가장 더운 곳이 가장 먼저 지원할 곳이다"
   - 앱: 기온, 고령 인구, 쉼터, 그늘 조건을 함께 보며 우선 지원 지역 변화 확인
   - 킥: 재난 취약성은 자연 현상과 공간 불평등이 겹치며 커진다
   - URL: `https://gwondalhyeon.github.io/AI-teacher-training/webapps/heat-vulnerability-map/`

3. **계약 성립·효력 판단기** (법과 사회)
   - 직관: "계약서는 곧 계약의 전부다"
   - 앱: 사례와 조건 토글 → 계약 성립, 취소 가능, 무효 가능, 채무 불이행 흐름 변화
   - 킥: 계약은 서명 여부보다 의사 합치와 효력 요건을 따지는 과정이다
   - URL: `https://gwondalhyeon.github.io/AI-teacher-training/webapps/contract-validity-checker/`

**대체 시연 후보**

| 앱 | 쓰기 좋은 상황 |
|----|----------------|
| 전자기 유도 | "가까움"이 아니라 "변화율"이 핵심이라는 과학 개념을 보여주고 싶을 때 |
| 스마트 도시 균형 실험실 | 기술 도입이 편리성, 비용, 개인정보, 신뢰를 동시에 움직이는 사례를 보여주고 싶을 때 |
| 모두를 위한 도시 예산 배분 | 제한된 자원 배분과 집단별 체감 차이를 토론으로 연결하고 싶을 때 |
| 상속 관계 가계도 시뮬레이터 | 법적 순위, 배우자 지위, 채무 조건이 함께 작동하는 조건부 판단을 보여주고 싶을 때 |

> ⏩ 시간 부족 시: 수학 사례 + 웹앱 목록 페이지 1분 소개 + 대표 사례 1개만 시연

### 실습: 직접 요청해보기 (10분)

참여자가 오늘 만든 조언자 또는 ChatGPT에 직접 웹앱을 요청한다. 바로 코드를 받기 전에, 먼저 자기 교과의 아이디어를 3줄로 정리하게 한다.

**아이디어 스케치**

    내 교과에서 깨고 싶은 직관:
    학생이 조작할 변수:
    화면에서 바로 보여야 하는 변화:

**슬라이드에 띄울 프롬프트**

    내 교과에서 학생들이 직관적으로 오해하는 개념 하나를 골라서,
    슬라이더나 버튼으로 값을 바꾸면 결과가 바뀌는 시각화 웹앱을
    HTML 파일 하나로 만들어줘. Tailwind CSS CDN을 써줘.
    학생들이 직접 조작해보면서 직관이 틀렸다는 것을 발견할 수 있게 설계해줘.

결과로 나온 코드를 `index.html`로 저장해 브라우저에서 열어보는 것까지 확인한다.

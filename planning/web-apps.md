# Web App Guidelines

## 철학

웹앱 시연의 목적은 두 가지다.

1. **수업 설계 관점 전달**: "어떤 순간에 웹앱이 수업의 킥이 되는가"를 직접 경험하게 한다
2. **가능성 인식**: "AI로 이런 것도 만들 수 있다"는 감각을 심는다

참여자가 보고 나서 얻어야 할 것은 "내 교과에도 학생들이 직관으로 틀리는 지점이 있는데, 거기에 쓸 수 있겠다"는 감각이다.

## 기술 스택

- GitHub Pages에서 구동 가능한 정적 파일만 사용
- 단일 `index.html` — Tailwind CSS CDN, vanilla JS
- 외부 API 호출 없음, 백엔드 없음

## 웹앱 제작 기준

좋은 웹앱의 조건:

1. **직관과 현실의 충돌**: 학생(또는 교사)이 가진 잘못된 직관이 있고, 그것을 시뮬레이션으로 깰 수 있다
2. **변수 조작 → 즉각적인 시각 변화**: 슬라이더·버튼으로 값을 바꾸면 결과가 바로 바뀐다
3. **아하 모먼트**: 정지된 설명이나 숫자로는 전달하기 어려운 개념이 움직임으로 이해된다
4. **교과 내용 밀착**: 교과서 내용을 그대로 다룬다. 교과 이름만 바꾸는 범용 도구가 아님

피해야 할 것:

- 퀴즈·OX 문제·분류 게임 형태 — 단순 상호작용, 교과 내용 이해와 직결 안 됨
- 정보 나열·비교표 수준 — 애니메이션·인터랙션 없이 텍스트만
- 입력받아 텍스트 출력하는 형태 — AI 챗봇 흉내

## Block 4 시연 설계

### 도입: 강사 수학 수업 사례 (10분)

**시연 앱**: `math-webapps/probability-statistics/sample-proportion-event-readiness/`

**수업 설계 의도 (강사 멘트 핵심)**

이 앱을 만든 출발점은 학생들이 가진 하나의 직관이다:

> "참석 확률이 70%니까 70%만 준비하면 충분하다."

이 직관은 틀렸다. 70%만 준비하면 10번 중 4번은 준비가 부족하다.
교과서로도 설명할 수 있지만, 직접 시뮬레이션을 돌려보면서 빨간 막대가 계속 나오는 걸 보는 경험이 다르다.

**앱 구조 설명 포인트**
- 상단 배너의 질문이 곧 수업의 출발점: *"이 판단, 얼마나 자주 틀릴까요?"*
- 슬라이더 3개(n, p, r)로 상황을 바꾸면 준비 부족 확률이 실시간으로 변한다
- "자동 실행" 버튼으로 수백 번 시뮬레이션 → 이론값과 실험값이 수렴하는 것을 본다
- 학습지가 앱과 함께 묶여 수업 시퀀스를 이룬다 (앱 없이 학습지만 쓰면 반쪽)

**강사가 전달할 수업 설계 흐름**

    학생 직관 확인 → 앱으로 직관 충돌 경험 → 학습지로 수치 확인 →
    여유 준비 비율 조절 실험 → 의사결정 토론

**연수 참여자에게 던질 질문**

> "여러분 교과에서 학생들이 틀린 직관을 갖고 오는 지점이 있나요?  
> 그 직관을 깨는 데 정지된 그림보다 움직이는 시뮬레이션이 더 효과적인 경우가 있나요?"

이 질문이 교사들이 자기 교과의 웹앱 아이디어를 떠올리는 계기가 된다.

### 이어지는 시연: 다른 교과 예시 (20분)

수학 사례에서 끌어낸 설계 원칙을 다른 교과 앱으로 확인한다.

**시연 순서 (권장)**

1. **수평 투사 운동** (통합과학1)
   - 직관: "빠르게 던지면 더 빨리 떨어질 것 같다"
   - 앱: 속력 슬라이더 → 수평 이동 거리는 달라지지만 낙하 시간은 동일
   - 킥: 수평·수직 운동의 독립성

2. **전자기 유도** (통합과학2)
   - 직관: "자석이 가만히 있어도 가까이 있으면 전류가 흐를 것 같다"
   - 앱: 자석 이동 방향·속도 슬라이더 → 이동할 때만 전류 발생
   - 킥: 변화율이 핵심이라는 것

> ⏩ 시간 부족 시: 수학 사례 + 1개만 시연

### 실습: 직접 요청해보기 (10분)

참여자가 ChatGPT 또는 자기 조언자에게 직접 웹앱을 요청한다.

**슬라이드에 띄울 프롬프트**

    내 교과에서 학생들이 직관적으로 오해하는 개념 하나를 골라서,
    슬라이더나 버튼으로 값을 바꾸면 결과가 바뀌는 시각화 웹앱을
    HTML 파일 하나로 만들어줘. Tailwind CSS CDN을 써줘.
    학생들이 직접 조작해보면서 직관이 틀렸다는 것을 발견할 수 있게 설계해줘.

결과로 나온 코드를 `index.html`로 저장해 브라우저에서 열어보는 것까지 확인한다.

## 교과별 주제 목록

강의에서 시연할 교과별 웹앱 후보. 위 시연 설계와 맞추어 선택한다.

### 수학 (강사 직접 제작 — `math-webapps` 별도 프로젝트)

| 앱 | 직관 충돌 | 아하 모먼트 |
|----|-----------|------------|
| 표본비율과 행사 준비 실험실 | "기댓값만큼 준비하면 충분하다" → 41.6%가 부족 | 표본비율의 변동성, 준비 여유의 의미 |

### 통합과학1

| 주제 | 핵심 인터랙션 | 아하 모먼트 |
|------|--------------|------------|
| 수평 투사 운동 | 초기 속력 슬라이더 → 궤적 애니메이션 | 수평 속력이 달라도 낙하 시간은 동일 |
| 원소 스펙트럼 | 원소 선택 → 방출 스펙트럼 선 표시 | 원소마다 고유한 선 위치 — 빛의 지문 |
| 분자 결합 모양 | 비공유 전자쌍 수 조절 → 분자 모양 변화 | 전자쌍 반발이 모양을 결정 |
| DNA 이중 나선 염기 쌍 | 염기 드래그 → 상보 결합 성립 여부 | A-T, G-C만 결합하는 상보성 |
| N형/P형 반도체 | 불순물 원소 선택 → 전하 운반체 시각화 | 도핑 종류에 따른 전자/양공 분포 (**비교표 형태 지양**) |

### 통합과학2

| 주제 | 핵심 인터랙션 | 아하 모먼트 |
|------|--------------|------------|
| 전자기 유도 | 자석 이동 방향·속도 → 유도 전류 방향·세기 | 정지 상태에서는 전류 없음, 변화율이 핵심 |
| 빛의 굴절·반사 | 입사각 슬라이더 → 굴절각·반사각 실시간 변화 | 전반사 임계각 체험, 스넬 법칙의 시각화 |
| 파동과 소리 | 진동수·진폭 슬라이더 → 파형 실시간 변화 | 진동수 = 높이, 진폭 = 크기 |

### 통합사회 (교과서 검토 후 확정)

| 주제 | 핵심 인터랙션 | 아하 모먼트 |
|------|--------------|------------|
| 수요·공급 곡선 | 곡선 이동 → 균형 가격·거래량 변화 | 외부 요인이 균형점을 움직이는 방향 |
| 기후 변화 지표 | 연도 슬라이더 → 기온·해수면 수치 변화 | 수십 년 데이터가 하나의 추세선으로 수렴 |

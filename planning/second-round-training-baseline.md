## 1. 기획 배경

1기 선정 과정 「AI와 대화하며 만드는 나만의 수업」은 다음 내용으로 구성되었다.

1. 생성형 AI 기초와 프롬프트 실습
2. 교과별 수업 설계 AI 조언자 만들기
3. AI 조언자와 수업 설계 및 명세서 작성
4. 바이브코딩으로 웹 학습도구 만들기

2기 운영계획은 2024년 2기부터 2026년 1기까지 이미 개설된 연수를 선정 대상에서
제외한다고 명시한다. 따라서 2기 과정은 1기 과정의 제목과 활동을 반복하지 않고,
출발 자료, 대상 교과, 제작 과정, 최종 산출물에서 차별성을 명확히 보여야 한다.

## 2. 과정의 기본 방향

### 확정 과정명

**로컬 AI로 다시 만드는 수학 수업자료: 웹 학습도구와 탐구 학습지**

최종 과정명은 위 문안으로 확정한다. 다음 요소를 반영한 결과다.

- 수학 교과에 특화된 과정임이 드러날 것
- 교사가 보유한 한글·PDF 수업자료에서 출발할 것
- 웹 학습도구와 학생 탐구 학습지를 함께 완성할 것
- 1기에서 사용한 ‘AI와 대화’, ‘나만의 수업’, ‘바이브코딩’ 중심 표현을 반복하지 않을 것

### 한 문장 정의

교사가 보유한 한글·PDF 교수학습자료를 내 컴퓨터의 생성형 AI로 분석·재구성하고,
자료 속 수학 개념을 조작 가능한 웹 학습도구로 구현·배포한 뒤 학생 탐구 학습지와
연결하는 12시간 실습형 연수

### 핵심 흐름

1. 내 한글·PDF 수업자료를 AI가 읽을 수 있게 가져온다.
2. 그 자료의 수학 개념을 움직이는 웹 학습도구로 만든다.
3. 학생이 접속할 수 있는 주소로 배포한다.
4. 웹 학습도구를 활용하는 탐구 학습지를 완성한다.

### 로컬 AI 운영 원칙

특정 로컬 AI 서비스를 연수의 기준 도구로 고정하지 않는다. 참여자는 자신이 이미 사용하고
있거나 사용 가능한 Codex, Claude Code, Antigravity 등의 서비스를 그대로 사용한다.

연수에서는 제품별 화면이나 명령어보다 다음 공통 작업 흐름을 가르친다.

1. 작업 폴더 열기
2. 프로젝트 설명과 제작 계획서 읽히기
3. 기존 파일 읽기
4. 새 파일 생성 및 기존 파일 수정
5. 명령 실행과 결과 확인
6. 오류 내용을 전달하고 수정 요청
7. 변경 결과 검토
8. GitHub 저장 및 웹 주소 게시

정적 HTML 웹앱, Markdown 학습지, GitHub Pages 배포는 주요 로컬 AI 서비스가 공통으로
지원할 수 있는 작업 범위로 본다. 단, HWPX·PDF·Office 문서 처리는 로컬 AI 제품의 기본
기능이 아니라 별도의 문서 도구·스킬 설치 여부에 따라 달라진다. 따라서 로컬 AI 제품이
아니라 다음을 공통 표준으로 삼는다.

- 동일한 프로젝트 폴더 구조
- 동일한 입력·출력 파일 형식
- 동일한 문서 읽기·변환·편집 도구
- 동일한 제작 계획서와 검수 기준
- 동일한 개인정보·저작권 보호 원칙

제품별 설치·로그인·화면 조작은 별도의 1쪽 안내 카드로 제공한다. 공통 강의 중에는
특정 제품의 고유 기능을 필수 활동으로 사용하지 않는다.

## 3. 해결하려는 현장 문제

- 많은 교사가 교수학습자료를 HWPX, HWP, PDF, DOCX, XLSX, PPTX 등의 형식으로
  보유하고 있으나, 생성형 AI가 이를 어떻게 읽고 수정하도록 해야 하는지 알기 어렵다.
- 로컬 AI를 처음 사용하는 교사는 작업 폴더, 프로젝트, 프롬프트, 맥락, 제작 계획서,
  스킬과 도구의 관계에 익숙하지 않다.
- 생성형 AI로 웹앱 코드를 만들 수 있어도, 수학적 정확성을 검증하고 학생이 접속할 수
  있는 주소로 배포하는 과정에서 어려움을 겪는다.
- 웹앱을 제작하더라도 학생의 예상·조작·관찰·설명·일반화로 이어지는 학습지가 없으면
  수업 활동이 단순 체험으로 끝날 수 있다.
- 저작권 교재, 학생 개인정보, 학교 내부 문서를 공개 저장소에 올릴 위험이 있으므로
  비공개 원본과 공개 가능한 결과물을 분리하는 작업 습관이 필요하다.

## 4. 연수 목표

연수 참여자는 12시간 후 다음을 할 수 있어야 한다.

1. 내 컴퓨터의 파일을 직접 읽고 수정하는 생성형 AI의 기본 작동 방식을 설명한다.
2. 프롬프트, 작업 폴더, 프로젝트, 맥락, 제작 계획서의 역할을 구분한다.
3. HWPX·PDF 교수학습자료를 AI가 분석하기 쉬운 문서 형식으로 변환한다.
4. 원본을 보존하면서 문서의 내용과 서식을 목적에 맞게 수정한다.
5. 기존 수업자료의 수학 개념과 학생의 어려움을 분석하여 웹 학습도구를 설계한다.
6. 생성형 AI와 함께 정적 웹앱을 제작하고 수학적·기능적 오류를 수정한다.
7. 웹앱을 학생이 접속할 수 있는 주소로 게시한다.
8. 웹앱과 연계된 탐구 학습지를 Markdown으로 작성하고 PDF 또는 HWPX로 출력한다.
9. 개인정보·저작권 자료와 공개 가능한 결과물을 구분하여 관리한다.

### 기획안에 반영할 차별화 문장

> 생성형 AI의 사용법을 체험하거나 단발성 콘텐츠를 생성하는 데 머무르지 않고,
> 교사가 실제 보유한 교수학습자료를 분석하는 단계부터 수학 웹 학습도구 제작,
> 현장 배포, 학생 탐구 학습지 구성까지 하나의 수업자료로 완성하도록 하고자 함.

### 확정된 기획 목적 문안

□ 학교 현장에는 한글·PDF·MS Office 형식의 교수학습자료가 많이 축적되어 있으나,
이를 로컬 AI로 직접 읽고 수정하여 새로운 수업자료로 재구성하는 경험은 부족했음.
이에 생성형 AI 활용을 대화 중심에서 실제 파일 기반의 수업자료 제작으로 확장하고자 함.

□ 기존 교수학습자료에서 학생이 어려워하는 수학 개념과 변화 요소를 분석하고,
학생이 값을 직접 조작하며 결과를 관찰할 수 있는 웹 학습도구로 구현함. 제작한 도구의
정확성과 사용성을 검토하고 학생이 접속할 수 있는 웹 주소로 배포하는 전 과정을 경험하게 함.

□ 웹 학습도구를 예상–조작–관찰–설명의 흐름을 갖춘 탐구 학습지와 연결하고,
Markdown 원본을 PDF·HWPX 등 학교 현장에서 활용 가능한 형식으로 완성함으로써
생성형 AI 활용이 실제 수업 준비와 교실 적용으로 이어지도록 하고자 함.

### 확정된 기대 효과 문안

□ 한글·PDF·MS Office 형식의 기존 교수학습자료를 로컬 AI로 분석·재구성하고,
수학 웹 학습도구를 제작·검증·배포하는 전 과정을 경험함으로써 교사의 AI·디지털 기반
교수학습자료 제작 역량을 높임.

□ 학생이 수학적 변화를 직접 조작하고 관찰할 수 있는 웹 학습도구와 탐구 학습지를
함께 완성함으로써 추상적인 수학 개념의 이해와 학생 참여를 높이고, 연수 결과물이
실제 수업에 적용되도록 함.

### 1차시. 내 수업자료를 AI 작업공간으로 가져오기

운영: 1주차 오전, 3시간

주요 내용:

- 내 컴퓨터의 파일을 직접 다루는 생성형 AI 이해
- 기본 작업환경 설치와 안전한 폴더 구성
- 프롬프트, 프로젝트, 제작 계획서의 기본 개념
- 한글·PDF·Office 교수학습자료 읽기
- 수업자료를 AI가 분석·편집하기 쉬운 문서로 변환
- 원본 보호, 저작권 및 개인정보 관리

차시 산출물:

- 작동하는 로컬 AI 환경
- 변환·정리된 기존 수업자료
- 개인 수업자료 작업 폴더

제출용 설명:

> 교사가 보유한 한글·PDF·Office 자료를 생성형 AI가 활용할 수 있는 형태로 변환하고,
> 원본을 보호하며 안전하게 수정하는 방법을 실습함.

### 2차시. 수업자료에서 움직이는 수학 학습도구 만들기

운영: 1주차 오후, 3시간

주요 내용:

- 기존 수업자료에서 학생이 어려워하는 개념 찾기
- 정적인 자료로 설명하기 어려운 수학적 변화 선정
- 학생이 조작할 요소와 관찰할 결과 설계
- 웹 학습도구 제작 계획서 작성
- 생성형 AI와 웹앱 1차 버전 제작
- 수학적 오류와 기능 확인

차시 산출물:

- 웹 학습도구 제작 계획서
- 작동하는 수학 웹앱 1차 버전

제출용 설명:

## 9. 문서 처리 원칙

### 읽기·변환과 정밀 편집을 구분한다

- HWP/HWPX/PDF/XLSX/DOCX/이미지 읽기 및 Markdown 변환: `kordoc`
- 기존 HWPX의 표·문단·서식을 보존하는 정밀 편집: `python-hwpx` 또는 HWPX 전용 도구
- DOCX·XLSX·PPTX 수정: 파일 형식에 맞는 전용 문서 도구
- Markdown에서 PDF 생성: PDF 생성·렌더링 도구
- 생성·수정 후: 원본 대조, 재열기, 화면·출력 상태 검수

### 변환은 원본 서식 복원이 아니다

```text
PDF → Markdown
내용을 재사용하기 위한 추출

Markdown → PDF
같은 내용을 새로 조판하여 출력
```

PDF를 Markdown으로 변환한 후 다시 PDF로 만들더라도 원본의 페이지와 서식이 그대로
복원되는 것은 아니다.

### 원본을 직접 덮어쓰지 않는다

```text
원본 → 읽기·분석 → 작업용 Markdown → 새 출력 파일
```

### 한 파일에 여러 편집 도구를 번갈아 적용하지 않는다

한 파일당 한 도구를 기준으로 작업하고, 결과 파일을 다시 열어 확인한다.

## 10. 개인정보·저작권·공개 범위

- 저작권 교과서·지도서·참고자료와 학생 개인정보 파일은 `private-sources/`에 보관한다.
- `private-sources/`, 임시 작업 폴더, 출력 중간 파일은 `.gitignore`에 추가한다.
- 공개 저장소에는 교사가 직접 만든 웹앱과 공개 가능한 학습지만 올린다.
- 학생 이름, 학번, 성적, 연락처, 상담 내용은 AI 서비스와 공개 저장소에 입력하지 않는다.
- 원본 자료의 이미지와 본문을 웹앱에 그대로 복제하지 않는다.
- 수학 내용과 계산 결과는 강사 또는 참여자가 직접 검증한다.
